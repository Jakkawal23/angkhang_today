### ผลเสียของการโพสต์ในกลุ่ม
- คอมเมนต์เป็นร้อย ไล่อ่านไม่ไหว
- **มิจฉาชีพใช้โพสต์หาห้องเป็นช่องทางหาเหยื่อ** — ตอบคอมเมนต์ / ทักแชตด้วยเพจปลอมที่ก๊อปรูปและชื่อที่พักจริง แล้วให้โอนมัดจำเข้าบัญชีม้า
- ผู้ใช้ไม่มีทางตรวจว่าเบอร์ / LINE / เลขบัญชี เป็นของเจ้าของจริงหรือไม่

แหล่งอ้างอิงรูปแบบการหลอกลวง: ข่าวเตือนเพจที่พักปลอมช่วงเทศกาล (Thai PBS Verify, InfoQuest, ธนาคารกรุงเทพ, กรมประชาสัมพันธ์)

## 4. SEO + AEO ที่ทำไว้

- **Static HTML ทุกหน้า** (Astro SSG) — Google และ AI crawler อ่านเนื้อหาได้ทันทีโดยไม่ต้องรัน JavaScript, โหลดเร็วบนมือถือ
- `<title>` / meta description / canonical / Open Graph / Twitter card ทุกหน้า
- JSON-LD: `LodgingBusiness | Resort | BedAndBreakfast | Campground`, `BreadcrumbList`, `FAQPage`, `ItemList`, `WebSite`+`SearchAction`, `Organization`
- **FAQ อัตโนมัติ** ทุกหน้าที่พัก (ราคาเท่าไหร่ / อยู่ตรงไหน / รองรับกี่คน / ติดต่อทางไหน) — ตอบตรงประโยคแรก เพื่อให้ AI หยิบไปตอบ
- ย่อหน้า "คำตอบสั้น" บนหน้าโซนและหน้าความปลอดภัย (answer-first)
- `/llms.txt` สรุปทั้งเว็บเป็นข้อความล้วนสำหรับ AI search (สร้างอัตโนมัติจากข้อมูล)
- `sitemap-index.xml` อัตโนมัติ, `robots.txt` อนุญาต GPTBot / PerplexityBot / ClaudeBot / Google-Extended
- หน้าหมวดที่ยังไม่มีที่พักจะใส่ `noindex` อัตโนมัติ (กัน thin content)
- URL ภาษาอังกฤษสั้น อ่านง่าย: `/stays/pine-hill-resort`, `/zones/ban-khum`

## 5. แผนเฟสถัดไป

1. **ใส่ข้อมูลจริง** + รูปภาพ (ลบไฟล์ตัวอย่าง `sample: true`)
2. **ย้ายข้อมูลไปฐานข้อมูล** — โครงสร้าง field ใน `src/content.config.ts` ใช้เป็น schema ของตารางได้ทันที; Astro รองรับ content loader จาก API/DB โดยไม่ต้องแก้หน้าเว็บ
3. ระบบหลังบ้านให้เจ้าของอัปเดตห้องว่าง / ราคา
4. ระบบจอง + ชำระเงินผ่านเว็บ (รับค่าคอมมิชชั่น) — เปลี่ยน Astro เป็นโหมด hybrid (SSR บางหน้า) ได้โดยไม่ต้องเปลี่ยน framework
5. พื้นที่โฆษณา (แบนเนอร์ / ที่พักแนะนำแบบเสียเงิน — ต้องติดป้าย "โฆษณา")
6. เพิ่ม collection ใหม่: สถานที่ท่องเที่ยว (`/places`), ร้านอาหาร/คาเฟ่ (`/eat`), ข่าวสภาพอากาศ / ดอกไม้บาน (`/today`) — ตรงกับชื่อ "Today"
7. รายงานเพจปลอม (รับแจ้งจากผู้ใช้) และ "บัญชีดำ" ที่ค้นได้ในหน้าตรวจสอบ
